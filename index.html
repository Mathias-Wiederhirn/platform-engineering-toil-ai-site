Step-by-Step to Reduce Toil with AI

A practical method: JIRA shows demand, Icinga shows operational signals, SOPs show manual actions and the Denis tool can use these inputs to propose incident resolutions, decisions, workflows, automation candidates and measurable KPI reduction.

1. Collect

  • JIRA: incidents, requests, comments, SLAs
  • Icinga: alerts, host, service, duration, recurrence
  • SOPs: symptoms, steps, commands, rollback

2. Enrich With AI

  • Clean and classify records
  • Group similar issues
  • Correlate tickets, alerts, SOPs, logs and deployments

3. Validate And Automate

  • Validate with resolver or service owner
  • Create the platform backlog
  • Transform into self-service and IaC
1

Identify Repetitive Manual Work

How To Do It

  • Export JIRA tickets from the last 3 to 6 months
  • Export recurring Icinga alerts
  • List SOPs that are executed often
AI Process: Toil DetectionGroups tickets, alerts and SOPs that describe the same recurring problem. Creates families such as access, certificates, monitoring, environment, deployment, firewall and database.

Expected output: Toil inventory with topic, volume, impacted service, affected team, data source and linked SOP.
Denis tool integration: The tool can ingest JIRA incidents, matching Icinga alerts and linked SOPs to show recurring incident families.
2

Measure Frequency And Impact

How To Do It

  • Count JIRA tickets by topic
  • Measure resolution time and reopened tickets
  • Measure Icinga alert duration and recurrence
AI Process: Scoring And PrioritizationCalculates a simple score: volume + time lost + risk + user impact + SOP complexity. High-score items become the first candidates.

Expected output: Top 10 topics to automate or standardize first.
Denis tool integration: The tool can rank incident families and display which ones create the most toil.
3

Standardize Runbooks And Interfaces

How To Do It

  • Compare similar SOPs
  • Define required fields
  • Choose standards for naming, owner, tags and thresholds
AI Process: Golden Path DesignTurns a family of tickets and SOPs into a standard path: request form, runbook, validation criteria, approval conditions and rollback.

Expected output: Golden path ready to publish in the platform catalog.
Denis tool integration: The tool can propose the minimum required fields and the standard resolution path for each recurring incident type.
4

Automate Safe Repeatable Actions

How To Do It

  • Select stable, well-understood SOPs
  • Start with low-risk actions
  • Add validation, logs, approvals and rollback
AI Process: SOP-To-AutomationConverts SOP steps into draft Ansible, Terraform, scripts, or CI/CD pipelines. Flags sensitive actions for human validation.

Expected output: Versioned automation draft, tested and reviewed by a human.
Denis tool integration: The tool can turn validated resolution steps into automation candidates with required checks and rollback notes.
5

Integrate Tools And Data Flows

How To Do It

  • Connect JIRA, Icinga, CI/CD and SOP documentation
  • Link ticket, alert, service and deployment
  • Write automation status back to JIRA
AI Process: Correlation And EnrichmentRebuilds the timeline: ticket opened, Icinga alert, recent deployment, logs, metrics, SOP used and action applied.

Expected output: Enriched incident context, likely cause and available evidence.
Denis tool integration: The tool can show the evidence trail behind each proposed resolution.
6

Add Observability And Feedback Loops

How To Do It

  • Track noisy Icinga alerts and recurring incidents
  • Measure automation success, failure and duration
  • Update SOPs and Icinga thresholds after incidents
AI Process: Feedback AnalysisDetects whether automation is really reducing toil. Suggests Icinga thresholds, SLO controls and runbook improvements.

Expected output: Dashboard with avoided tickets, reduced alerts, time saved and failures to fix.
Denis tool integration: The tool can learn from accepted and rejected resolution proposals to improve future recommendations.
7

Continuously Improve And Retire Toil

How To Do It

  • Review top JIRA tickets and top Icinga alerts every month
  • Remove obsolete SOPs
  • Feed the Platform Engineering backlog
AI Process: Continuous ImprovementProduces the monthly toil report, detects new patterns, proposes the next golden paths and estimates potential value.

Expected output: Prioritized backlog to standardize, create self-service, automate, improve alerting or retire a procedure.
Denis tool integration: The tool can create monthly improvement suggestions from recurring incidents, noisy alerts and manual SOP usage.

Minimum Vital Information Per Source

JIRA

  • Clear title
  • Impacted service or application
  • Start and end date/time
  • Symptom
  • Applied resolution
  • Resolver or team
  • SOP used
  • Time spent

Icinga

  • Host
  • Service check
  • State
  • Start and return-to-OK timestamp
  • Exact check message
  • Duration
  • Recurrence
  • JIRA link if possible

SOP

  • Procedure name
  • Covered symptoms
  • Exact steps
  • Commands or tools
  • Success validation
  • Rollback
  • Owner
  • Last update date

What AI Can Do When Vital Information Is Missing

Complete The Context

  • Compare a weak JIRA ticket with Icinga alerts from the same time window
  • Find the closest matching SOP by symptom, command, or service name
  • Suggest missing fields such as impacted service, likely action, owner and time spent

Separate Fact From Guess

  • Label information as confirmed, likely, or unknown
  • Show the evidence source: JIRA, Icinga, SOP, logs, CI/CD, or resolver comment
  • Never turn an unvalidated guess into automation

Improve The Next Ticket

  • Ask the resolver only for the missing vital information
  • Draft a clean resolution summary for review
  • Write validated context back to JIRA and the improvement backlog

How To Identify Toil KPIs And Calculate Reduction

Identify KPI Candidates

  • Start from repeated JIRA tickets and requests
  • Add recurring Icinga alerts and noisy checks
  • Map each item to the related SOP and manual actions
  • Keep KPIs measurable before and after improvement

Build The Baseline

  • Ticket volume per month
  • Average resolution time
  • Manual time spent per ticket
  • Alert count and alert duration
  • Number of SOP executions
  • Reopen rate or failed automation rate

Calculate Reduction

  • Use the same KPI before and after the change
  • Compare the same period length, such as 30 days vs 30 days
  • Track monthly to avoid one-time noise
  • Confirm results with the service owner
Reduction % = (Baseline - Current) / Baseline x 100

Recommended KPI Set For Toil Reduction

Demand KPIs

  • JIRA tickets per toil category
  • Repeated requests per service
  • Mean time to resolve
  • Waiting time between handoffs
  • Self-service adoption rate

Operational KPIs

  • Icinga alerts per service
  • Noisy alert rate
  • Mean time to acknowledge
  • Mean time to recover
  • After-hours interruptions

Automation KPIs

  • SOP executions replaced by automation
  • Manual steps removed
  • Automation success rate
  • Automation rollback rate
  • Estimated hours saved per month
